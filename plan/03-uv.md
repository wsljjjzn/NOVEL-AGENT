# 03 — uv 化与双环境分离

**目标**：① 开发环境与运行环境分开 ② `uv run` 能看清所有入口 ③ 换供应商只改 yaml。

> 版本前提：本项目已用 uv **0.13.0**（`uv.lock` 在库中）。UV 0.13 默认 Python 已是 3.15，**本项目锁定 3.11+**（Pydantic AI 要求 `>=3.11`）。

---

## 1. 双环境分离：核心机制

uv 用 **extras**（可发布的可选依赖）与 **dependency-groups**（本地开发依赖，不进发布元数据）区分两类东西。

**关键陷阱（必须避坑）**：
uv **默认会把 `dev` 组装进环境**。若把 pytest 放在 `dev` 组，则"运行环境"里仍有 pytest——**开发与运行没分开**。

**解法**：把开发工具放进组（`dev` / `lint`），并设

```toml
[tool.uv]
default-groups = []      # 默认什么都不装
```

这样：

| 命令 | 装了什么 | 用途 |
|---|---|---|
| `uv sync` | **只有核心运行依赖** | 运行/生产 |
| `uv sync --group dev` | + pytest | 开发 |
| `uv sync --group dev --group lint --extra ai` | + ruff/mypy/LLM 层 | 完整开发 |

**注意**：上面 `uv sync`（不传 `--no-default-groups`）之所以干净，是因为改了 `default-groups = []`。这是与"不设该字段"的关键区别。

---

## 2. 依赖分组的理由

| 分组 | 内容 | 什么时候装 |
|---|---|---|
| **核心** `[project.dependencies]` | pydantic / pydantic-settings / pyyaml / python-dotenv / rich / textual / loguru / chardet / tqdm | 永远 |
| **`[ai]`** extra | `pydantic-ai-slim[openai]`、`mcp` | 需要 LLM 调用或 MCP 服务器时 |
| **`[gpu]`** extra | torch 系、`sentence-transformers`、`chromadb`、`rank-bm25`、`FlagEmbedding`、`jieba` | 只在跑 60GB 语料预处理时 |
| **`dev`** group | pytest、pytest-asyncio | 开发/CI |
| **`lint`** group | ruff、mypy | 开发/CI |

**为什么 `ai` 是 extra 而不是核心**：
领域引擎（`src/novel/*`）是**零 LLM 依赖**的。把 `ai` 做成 extra，就**用依赖图强制了那条架构约束**——想用领域引擎不必装 LLM 框架，装错了也 import 不到。

**为什么 `gpu` 单独**：
它是数 GB 的 torch 系。CLI 与 MCP 都不需要它。CI 里**不装** `gpu`。

## 3. 完整 pyproject.toml 设计

```toml
[project]
name = "novel-agent"
version = "0.2.0"
description = "写作专家系统：长篇小说状态引擎（MCP 服务器 + 模型无关 LLM 层）"
readme = "README.md"
requires-python = ">=3.11"

dependencies = [
    "pydantic>=2.12",
    "pydantic-settings>=2.0",
    "pyyaml>=6.0",
    "python-dotenv>=1.0",
    "rich>=13.0",
    "textual>=6.2",
    "loguru>=0.7",
    "chardet>=5.0",
    "tqdm>=4.65",
]

[project.optional-dependencies]
# LLM 调用层 + MCP 服务器。领域引擎不需要它 —— 依赖图即架构约束
ai = [
    "pydantic-ai-slim[openai]>=2.55",
    "mcp>=2.3",
]
# 60GB 语料预处理。数 GB 级，CI 不装
gpu = [
    "torch>=2.2",
    "sentence-transformers>=2.2",
    "chromadb>=0.5",
    "rank-bm25>=0.2",
    "FlagEmbedding>=1.2",
    "jieba>=0.42",
]

# 入口点。uv run（无参）会列出这些
[project.scripts]
na = "src.interfaces.cli.main:main"
na-tui = "src.interfaces.tui.app:run"
na-mcp = "src.interfaces.mcp.server:main"
na-tools-preprocess = "src.tools_scripts.preprocess:main"
na-tools-index = "src.tools_scripts.build_index:main"
na-tools-doctor = "src.interfaces.doctor:main"

[dependency-groups]
dev = ["pytest>=8.0", "pytest-asyncio>=0.23"]
lint = ["ruff>=0.6", "mypy>=1.11"]

[tool.uv]
# ⚠️ 关键：不默认装任何组 → 开发与运行分离
default-groups = []
# 本项目是应用不是库，但需要入口点 → 必须 true（原为 false）
package = true

[tool.pytest.ini_options]
testpaths = ["tests"]
addopts = "-q"
markers = ["spike: 一次性验证，不作为回归测试"]

[tool.ruff]
line-length = 100
target-version = "py311"

[tool.ruff.lint]
select = ["E", "F", "I", "UP", "B", "SIM"]
ignore = ["E501"]

[tool.mypy]
python_version = "3.11"
warn_unused_ignores = true
disallow_untyped_defs = false   # 渐进收紧
```

### 三处必须一起改的**破坏性**变更

| 变更 | 原值 | 新值 | 为什么必须改 |
|---|---|---|---|
| `requires-python` | `>=3.10` | **`>=3.11`** | Pydantic AI 要求 `>=3.11` |
| `openai` 依赖 | `>=1.0.0` | **`>=3.26.0`** | `pydantic-ai-slim` 要求 `>=3.26.0`。本机 3.3.0 满足，但**干净机器新装会解析出 1.x 并冲突** |
| `[tool.uv] package` | `false` | **`true`** | **`package = false` 时无法定义入口点**。不给包就没有 `uv run na` |

## 4. `uv run` 清晰可见的设计

### 4.1 为什么 `uv run`（无参）能列出入口

`uv run` 不带参数时会**列出项目里可运行的东西**——这依赖 `[project.scripts]` 已声明。所以：

```bash
uv run                # → 列出 na / na-tui / na-mcp / na-tools-*
uv run na --help      # → CLI 三组
uv run na-tools-doctor
```

### 4.2 暴露 vs 隐藏的原则

| 处理 | 什么 | 理由 |
|---|---|---|
| **暴露成入口** | CLI、TUI、MCP、doctor、预处理、建索引 | 有稳定用途，人和 agent 都可能调用 |
| **暴露成 CLI 子命令** | novel/article/kb 三组 18 个命令 | 已在 `na` 下，不必各成一个入口 |
| **隐藏** | `scripts/` 下 14 个 `_` 前缀一次性脚本 | **删除**，不是隐藏 |
| **隐藏** | `data/preprocess_checkpoint.json` 类内部状态 | 非入口 |
| **不暴露** | 内部模块级 `__main__` | 需要时用 `python -m src.x.y`，不进入口表 |

**原则**：入口表是**契约**。每多一个入口就多一个要维护的 API。不稳定的东西不要进。

### 4.3 现有 `tui.py` / `main.py` 的处置

两者都在做 `sys.path.insert` 的路径 hack——**装了包之后不需要**。

- 改为**兼容 shim**（保留一版，打印迁移提示后转调新入口），下个版本删除
- `main.py` 的 `--mode` 参数里 `api` / `gradio` / `test` 三个分支**删除**：
  - `--mode test` 是空分支（只 import 不变量，无断言）
  - `--mode gradio` 已被项目自己在多处标注暂停
  - `--mode api` 依赖未安装的 fastapi

## 5. 验证清单（干净克隆后必须全部通过）

```bash
# ① 运行环境：只装核心，不含任何开发工具
uv sync
uv run python -c "import pytest"    # 必须报 No module named pytest
uv run na-tools-doctor

# ② 开发环境：加 dev 组
uv sync --group dev
uv run pytest                       # 全绿且不联网

# ③ AI 层
uv sync --extra ai
uv run na-mcp --help

# ④ 入口可见性
uv run                              # 必须列出 na / na-tui / na-mcp / na-tools-*
uv run na --help
```

**第 ① 条是双环境分离的证明**：`uv sync` 之后 `pytest` **不可导入**。

**CI 用**：

```bash
uv sync --extra ai --group dev --group lint
uv run ruff check . && uv run mypy src && uv run pytest
```

CI **不装 `--extra gpu`**。

## 6. 一次性脚本的处置

`scripts/` 下有 **14 个 `_` 前缀脚本**，定性为 throwaway。其中两个有副作用需单独确认：

| 脚本 | 处置 | 注意 |
|---|---|---|
| `_new_db.py` | **删除** | 它会**直接改写 `config/config.yaml` 且无备份** |
| `_reset_db.py` | **删除** | 删旧库 + checkpoint + embeddings。能力并入 `na-tools-doctor --reset` 并**要求二次确认** |
| `_refactor.py` | **删除** | 246 行代码生成器，已用完 |
| 其余 11 个 `_` 脚本 | **删除** | 一次性诊断 |
| `batch_preprocess.py` | → 入口 `na-tools-preprocess` | 保留 |
| `build_index_csv.py` | → 入口 `na-tools-index` | 保留 |
| `rebuild_outline.py` | → 入口 `na-tools-rebuild-outline` | 保留（默认 dry-run，`--apply` 前备份） |
| `tui_snapshot.py` | → `na-tools-snapshot` | 保留（无终端环境的排版验证） |
| `select_top_articles.py` / `purge_docs.py` | → `na-tools-select` / `na-tools-purge` | 保留，**`purge` 默认 `--dry-run`** |
| `learn_articles*.py` / `generate_conclusion*.py` / `extract_characters.py` / `import_analysis_to_kb.py` / `verify_db.py` / `run_gradio.py` / `integration_test.py` / `_benchmark.py` | **删除或归档到 `archive/`** | 一次性数据准备；`run_gradio.py` 随 gradio 一起删 |

**净效果**：`scripts/` 从 25 个文件降到约 6 个入口，且都在 `[project.scripts]` 里可见。

## 7. 常见错误

| 错误 | 后果 | 正确做法 |
|---|---|---|
| `uv add pytest` | 进**核心依赖**，污染运行环境 | `uv add --group dev pytest` |
| 依赖 `dev` 组分离环境 | `default-groups` 默认装 dev → **分离失败** | 设 `default-groups = []` |
| 保留 `package = false` | **入口点不生效**，`uv run na` 找不到 | 改 `true` |
| 用 `--no-default-groups` 代替改配置 | 每次都得记得传，**迟早忘** | 写进 `pyproject.toml` |
| CI 装 `--extra gpu` | CI 慢且体积大 | CI 只装 `ai` + `dev` + `lint` |
| 把 `openai` 留在 `>=1.0.0` | 干净机器解析到 1.x → 与 Pydantic AI 冲突 | 抬到 `>=3.26.0` |
