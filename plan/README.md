# plan/ — 执行计划

本目录是 **agent 的执行指南**。开工前先读本文件，确认你要做的事属于哪个阶段。

## 读法

| 文件 | 什么时候读 |
|---|---|
| `README.md`（本文件） | **每次开工前** |
| `00-phases.md` | 找自己的任务属于哪一阶段、前置条件是什么 |
| `01-tasks.md` | 开始做事：取任务、看验收标准、看写入范围 |
| `02-workflow.md` | 不确定怎么推进、怎么提交、怎么同步文档时 |

## 铁律

1. **一次只做当前阶段的事。** 下一阶段的任务即使看起来顺手，也不要动——阶段之间有前置依赖。
2. **文档先行。** 行为变更必须先改 `docs/` 再改代码（见 `02-workflow.md`）。
3. **不改计划外的东西。** 需要扩大范围时先问，不要自行决定。
4. **每个任务有写入范围。** 不要碰范围外的文件——多人/多 agent 并行时会冲突。
5. **验收标准是完成条件，不是建议。** 不满足就不算做完。

## 阶段总览

| 阶段 | 目标 | 前置 | 是否可并行 |
|---|---|---|---|
| **P0** 止血 | 契约收口，消除"假成功" | 无 | 否（改动集中） |

| **P2** 工具层 | 抽出 `src/tools/`，唯一操作真源 | P1 | 否（关键路径） |
| **P3** 双适配器 | CLI 与 MCP 都变成薄适配器 | P2 | **是**（CLI / MCP 各自独立） |
| **P4** LLM 层 | 换 Pydantic AI，删手写 JSON 容错；**含 DeepSeek FastPath** | P2 | 可（按调用点拆） |
| **P5** 模型无关 | provider 配置化，**新增** `--provider/--model`（`--tier` 保留为别名） | P4 | 否 |

**关键路径**：P0 → P1 → P2 → P3。
P4/P5 与 P3 可并行；P6 全程可渐进推进。

> **兼容性优先**：任何"加新参数"的改动都**保留旧参数为别名**。
> **且新参数止步于最外层**——不要为了让 `--provider` / `--model` 生效而改内部 API 签名。
> 详见 [`02-workflow.md`](02-workflow.md) 的「兼容性优先」一节。
